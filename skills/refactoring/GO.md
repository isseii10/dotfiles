# Go に当てはめるときの注意

カタログの手順には、Go では飛ばせるものも、別の工夫が要るものもある。合わないところは計画にそう書いて、合わせ方を決める。

## 道具に任せる

- 名前の変更とインライン化は、gopls（Rename、Inline call）に任せると呼び出し元まで漏れなく直る。
- 使われていない変数や import はコンパイルエラーになるので、変更で残ったものや消えたものにすぐ気づける。使われていないフィールドはエラーにならないので、Push Down Field などで消すときは参照を検索して確かめる。
- 消してよいかは、非公開なら staticcheck の `U1000` で、公開ならモジュール全体を検索して `go build ./...` で確かめる。

## Go にないものと、代わりの書き方

| ほかの言語にあるもの | Go での書き方 |
| --- | --- |
| オーバーロード | 公開 API で新旧を並べるときは別の名前にし、古い方に `// Deprecated:` を付ける |
| `assert` | 外から来うる不正な値は `error` を返す（シグネチャが変わるので、仕様の変更として扱う）。プログラマのミスだけなら `panic` |
| `map` / `filter` のチェイン | `for range` のまま、ループの中を整理するのがふつう。メソッドは型パラメータを持てないので、チェインは作れない。途中結果に名前を付けた変数を並べる |
| 名前付き引数 | `bool` 引数は意味が読めない。関数を分けるか、名前の付いた型にする |
| 読み取り専用の変数やフィールド | `:=` で1回だけ代入して、そのあと代入しないことで示す。フィールドは非公開にして setter を置かない |
| コンストラクタ | `NewXxx` は最初からファクトリ関数。インターフェースを返せば具体的な型を隠せる。ゼロ値で使える型には要らないことが多い。同じパッケージの中では構造体リテラルを禁止できない |
| `null` / `undefined` | 「見つからない」は `(T, bool)` で返す。ゼロ値がそのまま特殊ケースになることがある（空の構造体） |
| 継承 | 下の「埋め込みは継承ではない」を見る |
| 直和型と網羅チェック | 非公開メソッドを持つインターフェース（sealed interface）と型スイッチで、閉じた種類の集合を表す。網羅チェックはコンパイラがしないので、`exhaustive` や `go-sumtype` などのリンタで補う |

## 埋め込みは継承ではない

- 埋め込みは「フィールドとメソッドの自動転送」にすぎない。埋め込んだ型のメソッドの中から、外側の型で上書きしたメソッドは呼ばれない（仮想関数にならない）。だから、「スーパークラスのメソッドからサブクラスのメソッドを呼ぶ」形は、インターフェースを受け取る関数（`annualCost(p Party)`）で表す。
- データだけを共通にする埋め込み（共通のフィールドを持つ `base` 構造体）は素直に使える。
- Extract Superclass のスーパークラスは、Go では2つに分かれる。データの共通部分は埋め込む構造体、振る舞いの共通部分はインターフェースとそれを受け取る関数。どちらが要るかは別々に決める。
- 上書きを前提にしたポリモーフィズムは避ける。埋め込みで既定のメソッドを持たせると、書き忘れても気づけない。全部の型で違うなら埋め込まずに型を分け、書き忘れをコンパイルエラーにする。ほとんど同じなら埋め込んで、違いだけを書く。
- 外側の型を内側の型として渡すことはできない（`enriched.Reading` と取り出す）。公開型に埋め込むと、埋め込んだ型のフィールドとメソッドが全部、公開 API になる。名前がぶつかると外側が優先され、内側は黙って隠れる。
- 継承で書くような設計の多くは、Go では最初から委譲かインターフェースで書くのが素直な形になる。

## インターフェース

- `nil` のポインタを入れたインターフェースは `nil` と等しくならない。`nil` を特殊ケースに変えるのは、インターフェースに入れる前にする。
- ポインタレシーバーで `String()` を定義すると、値は `fmt.Stringer` として扱われない。
- インターフェースは使う側で小さく定義する（`io.Writer` を受け取れば、テストでは `strings.Builder` を渡せる）。インターフェースを受け取り、構造体を返す。

## カプセル化

- カプセル化の単位はパッケージ。同じパッケージからは非公開フィールドにも触れるので、アクセサを通すかどうかは自分で守る。
- 値型の構造体は、渡すだけでコピーになる。漏れるのは、ポインタ、スライス、マップを持っているときだけ（値型のコピーは浅い）。小さな値は値オブジェクトにすると、隠す手間が減る。値オブジェクトは比較可能なフィールドだけにすれば `==` で比べられる。
- コピーは `slices.Clone` で取る。`append` は容量に余裕があると元の配列に書き込むので、コピーしたつもりで共有していることがある。`maps.Clone` は浅いコピーなので、入れ子のマップは段ごとにコピーが要る。
- 1つの型に値レシーバーとポインタレシーバーを混ぜない。

## 細かい罠

- Replace Primitive with Object で `type Priority string` にすると、どんな文字列からでも `Priority("hoge")` と変換できてしまう。決まった値しか作らせないなら、`iota` の列挙型に `String()` を付ける。
- Rename Field で Go の名前を変えても、JSON タグがあればキーは変わらない。外とやりとりするキーまで変えるのは振る舞いの変更なので、別に判断する。
- 関数名とローカル変数がぶつかる（`totalDistance := totalDistance(points)`）。コンパイルは通るが、次の行から関数が隠れる。ローカル変数の名前を変える。
- 予約語や組み込み関数と同じ名前（`range`、`map`、`min`、`max`、`len`）を変数名に使わない。
- `float64` の `NaN` はどの比較でも `false` になる。`!(x > 0)` と `x <= 0` は `NaN` のときだけ違う結果になる。`NaN` を弾くなら `math.IsNaN` で明示する。
- パッケージ変数を書き換えるテストは、`go test -count=2` の2回目で落ちることがある。状態を共有するので `t.Parallel()` も使えない。
- macOS の `sed` では `\b` が効かない。一括置換のあとは、差分で実際に変わったことを確かめる。

## 仕上げ：Go らしい書き方に直す

ほかの言語から持ち込んだ書き方が残っていたら、臭いとして扱う。計画に入れるか、Step 4 の報告で候補として伝える。

- クロージャが入れ子になった長い関数 → パッケージレベルの関数にする。クロージャは外側の変数を黙って使うので、依存が見えない。外に出すと、依存が引数に出る。
- 大きな値を丸ごと渡している → 必要なものだけを受け取る関数にする。
- 作ってからフィールドを1つずつ埋める、setter で後から入れる → 複合リテラルか `NewXxx(...)` で一度に作る。作りかけの状態と、呼ぶ順番の罠がなくなる。
- `var x T` と宣言して、あとで代入する → Slide Statements で最初の代入の隣に寄せ、`:=` にまとめる。
- `append` を重ねてスライスを作る → スライスのリテラル1つにする。
- パッケージ変数（隠れた依存）→ 引数で渡し、`main` で作る。
- `return` のあとの `else` → `else` を外して、本筋を入れ子の外に出す。
- `GetXxx` という getter → `Xxx` にする。
